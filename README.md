# PayPal Delight AI

Demo Store для PayPal AI Hackathon 2026: покупка через PayPal Sandbox открывает право
на один персональный AI-подарок. Реализованы **этап 2 — Sandbox Checkout**,
**этап 3A — DE/EN и юридические страницы**, **этапы 3B/3C — полный цикл трёх Mock-подарков**.
После подтверждённой покупки можно создать, открыть и скачать подарок.
На выбор Caricature, Greeting Card и Mini Comic; одна покупка даёт только один подарок.
По умолчанию каждый режим использует подготовленную DEMO-иллюстрацию.
Stage 5 добавляет отключённый по умолчанию Cloudflare Workers AI Provider:
FLUX.2 klein 4B, локальные DE/EN надписи, согласие на фото и лимиты расходов.
Интеграция проверяется с имитацией API. Первая реальная генерация требует
настройки credentials и отдельного разрешения владельца.
Закрытая страница `/ai-lab` позволяет исследовать все три режима без новых покупок;
тесты не расходуют права на подарки. Общий бюджет — 50 попыток / 8000 расчётных
Neurons в сутки. Настройки описаны ниже, [порядок публикации — в deploy/README.md](deploy/README.md).

Интерфейс выбирает DE/EN по языкам браузера (fallback EN). Переключатель в шапке
сохраняет ручной выбор. `/legal` и `/privacy` содержат двуязычные черновики с явными
пометками для данных владельца и условий обработки; до публичного размещения их
нужно заполнить и проверить. PayPal SDK на этих страницах не загружается.

## Локальный запуск

Требования: Node.js **22.12+ в ветке 22.x**, npm **9+**. На Windows используйте
`npm.cmd`; на Linux/macOS — `npm`.

```powershell
npm.cmd ci
# Только если .env ещё не существует:
Copy-Item .env.example .env
```

Заполните в корневом `.env` `PAYPAL_CLIENT_ID` и `PAYPAL_CLIENT_SECRET` из
**Sandbox Business REST app** в PayPal Developer Dashboard. Без обоих значений
магазин доступен для просмотра, оплата отключена. Один заполненный ключ считается
ошибкой конфигурации. Не передавайте ключи в чат и не помещайте их в `VITE_*`.

Откройте два терминала **в корне проекта**:

```powershell
# Терминал 1: backend с перезапуском при изменениях
npm.cmd run dev:server
```

```powershell
# Терминал 2: frontend
npm.cmd run dev:client
```

Откройте **http://127.0.0.1:5173** — адрес должен совпадать с `APP_ORIGIN`.
Не заменяйте `127.0.0.1` на `localhost` без соответствующего изменения `.env`:
это другой origin и другая cookie-сессия. После изменения `.env` перезапустите
оба процесса. Для остановки используйте `Ctrl+C`.

[Пошаговая инструкция настоящей Sandbox-покупки](docs/SANDBOX_TESTING.md).

## Конфигурация

| Переменная | По умолчанию / назначение |
| --- | --- |
| `HOST` | `127.0.0.1`, адрес Fastify |
| `PORT` | `8003`, порт Fastify |
| `APP_ORIGIN` | `http://127.0.0.1:5173`, точный origin frontend без завершающего `/` |
| `DATABASE_PATH` | `data/delight.sqlite`, относительный путь считается от корня проекта |
| `PAYPAL_ENVIRONMENT` | Только `sandbox`; другое значение останавливает запуск |
| `PAYPAL_CLIENT_ID` | Client ID приложения Sandbox Business; публичная часть конфигурации SDK |
| `PAYPAL_CLIENT_SECRET` | Secret того же приложения; используется только сервером |
| `AI_PROVIDER` | `mock` по умолчанию; `cloudflare` для FLUX.2 klein 4B; `openai` не реализован |
| `AI_ENABLED` | `false`; разрешает внешний AI только при явном `true`, не отключает локальный mock |
| `AI_LAB_ENABLED` | `false`; закрытое тестовое студио без покупок |
| `AI_LAB_PROXY_TOKEN` | Только backend/Nginx; устанавливается защищённым deployment |
| `CLOUDFLARE_ACCOUNT_PLAN` | `free` после подтверждения тарифа; требуется для подготовки deployment |
| `NODE_ENV` | Для будущего размещения: `production` |

`.env` загружается встроенным механизмом Node.js; переменные окружения имеют
приоритет. Файл необязателен, если конфигурация уже передана через окружение.
В production обязательны HTTPS `APP_ORIGIN` и абсолютный `DATABASE_PATH`
**вне каталога релиза**, например `/var/www/paypal-delight-ai/shared/delight.sqlite`.
Production cookie имеет флаг Secure. API URL и SDK URL PayPal фиксированы на Sandbox;
Live переключателя нет даже при `NODE_ENV=production`.

## Три Mock-подарка — этапы 3B/3C/3D

- `server/src/gifts/provider.ts`: интерфейсы `GiftRequest`, `GiftResult`, `GiftProvider`
  и фабрика провайдеров. Вход: тип подарка, серверный товар, язык, пожелания до 500
  символов, имя получателя и повод (открытка), имя персонажа (комикс),
  необязательное подготовленное фото (только Caricature). Результат: PNG-байты, размер,
  язык, тип, текст и явный признак `isDemo`. Персональные данные не журналируются.
- Mock возвращает файл `server/src/assets/mock-<type>.png`: `caricature` (768×768),
  `greeting-card` (900×1100), `mini-comic` (1200×900, четыре панели в одном PNG).
  SVG-исходники нарисованы кодом и переведены в PNG через имеющийся Sharp; AI API
  не использовались. Товар, язык и персонализация принимаются провайдером,
  но не изменяют статичные изображения. DEMO обозначен в UI и на самих картинках.
- После генерации `server/src/gifts/branding.ts` через существующий Sharp добавляет
  отдельную полосу снизу: «A little delight after paying with PayPal» (EN) или
  «Ein kleines Extra nach dem Bezahlen mit PayPal» (DE) и небольшую подпись «Delight AI».
  Язык берётся из запроса подарка. Подписи в `gift-footer-en.svg` / `gift-footer-de.svg`
  переведены в векторные контуры; шрифты на сервере и внешние API не требуются.
  Логотип PayPal не используется. Исходная иллюстрация не обрезается и не перекрывается.
  Полоса увеличивает высоту на 11% ширины: новые PNG имеют размеры 768×852,
  900×1199 и 1200×1032 соответственно. Предпросмотр и скачивание используют один
  сохранённый PNG. Обработка общая для любого провайдера, без реализации OpenAI.
  Уже сохранённые подарки выдаются байт-в-байт без повторного брендирования.
  Для mock ошибка обработки сохраняет возможность повторной попытки.
  После отправки Cloudflare неоднозначная ошибка удерживает право в REVIEW;
  автоматической повторной генерации нет.
- `GET /api/gifts/demo/caricature.png` показывает только публичную демоиллюстрацию,
  помеченную `DEMO` и заголовком `X-Delight-Demo: true`. Это не выдача подарка:
  заказ и право на подарок не меняются. Новых публичных маршрутов генерации нет.
- `GiftFlow.vue` предоставляет форму, ожидание, результат и скачивание. После оплаты
  выберите один режим, заполните его форму и нажмите Create My Gift.
  Для Greeting Card обязательны имя получателя (до 80 символов) и повод (до 120),
  для Mini Comic — имя персонажа (до 80). Достаточно вымышленного имени/псевдонима.
  Пожелания необязательны (до 500). До отправки режим можно сменить; поля очищаются.
  `GiftPhotoInput.vue` позволяет выбрать и просмотреть необязательное фото только
  после отдельного согласия. Отзыв согласия или «без фото» очищает выбор.
  Фото отправляется только при создании подарка, в JSON/base64 существующего API.
- `withPreparedPhoto` проверяет согласие, размер (5 MiB), сигнатуру, MIME и декодирование
  JPEG/PNG/WebP, не допускает анимацию и более 16 MP. Sharp применяет ориентацию,
  уменьшает изображение до 511 px по стороне и пересоздаёт PNG без метаданных.
  Оригинал и очищенная копия обрабатываются в памяти: временные фотофайлы больше
  не создаются, включая аварийный выход. После вызова провайдера буферы очищаются
  в `finally`. Фото, имя файла, пожелания, введённые имена, повод и согласие
  не сохраняются отдельными полями в БД или логах. В Cloudflare-режиме готовое PNG
  может содержать введённый текст или созданное сходство; само PNG сохраняется.
- `POST /api/orders/:id/gift`: общие поля `{type, language: 'en'|'de', wishes}`.
  Для `caricature` допустим `photo?: {data: '<base64>', contentType, consent: true}`;
  Cloudflare дополнительно требует `photo.cloudflareConsent: true`.
  `greeting-card` требует `recipientName` и `occasion`, `mini-comic` — `characterName`.
  Неподходящие режиму поля и фото для открытки/комикса отклоняются.
  Цена и товар берутся
  из оплаченного заказа. Лимит тела только этого маршрута — 7 MiB для base64;
  лимиты самого изображения — 5 MiB / 16 MP. Заказы и подарки проверяются по cookie.
- `GET /api/orders/:id/gift` возвращает подтверждённый заказ и состояние подарка.
  `/api/orders/:id/gift/image` и `/download` выдают PNG только владельцу после
  завершения. Download задаёт имя `delight-<сохранённый тип>-<order UUID>.png`.
- Успешный POST возвращает уже сохранённый результат при любом повторе.
  Переключение режима после успеха также возвращает прежний подарок. Блокировка
  общая для заказа, а не для режима. При параллельной обработке возвращается
  202 / GENERATING; frontend опрашивает GET.
  Для mock ошибка сохраняет право на повтор. Cloudflare при неопределённом исходе
  возвращает REVIEW до решения оператора. Подарок восстанавливается после reload и restart.
  В магазине доступен список «Your purchases & gifts» / «Deine Einkäufe & Geschenke»:
  он загружается с сервера по cookie и показывает все подтверждённые покупки,
  готовые подарки и неиспользованные права. Можно сохранить `/?order=<UUID>`.
  `delight-checkout` восстанавливает только незавершённую попытку и очищается
  после подтверждения оплаты. Просмотр старого подарка не меняет ID новой покупки.
- Сборка backend копирует PNG в `server/dist/assets/`; будущий релиз должен включать
  весь `server/dist`, сохраняя entrypoint `server/dist/index.js`.

## Как работает покупка

1. `GET /api/store` возвращает три товара с серверными ценами EUR, публичную
   конфигурацию SDK и устанавливает случайную HttpOnly cookie-сессию покупателя.
2. Официальный JS SDK v6 загружается с `www.sandbox.paypal.com/web-sdk/v6/core`.
   Используются `createInstance`, проверка eligibility в EUR и
   `createPayPalOneTimePaymentSession`. Поддержаны onApprove/onCancel/onError и
   возобновление redirect-сессии через hasReturned/resume.
3. `POST /api/orders` принимает только `productId` и UUID `requestId` попытки.
   Сервер сохраняет снимок товара и суммы в SQLite, затем создаёт Orders API v2
   Order. Цена, валюта, статус, merchant и PayPal ID не принимаются от браузера.
4. После одобрения покупателем `POST /api/orders/:id/capture` сначала читает
   сервером PayPal Order, проверяет его и выполняет Capture только для APPROVED.
   Затем заново читает полный заказ: сокращённый ответ Capture не используется
   как единственное доказательство оплаты.
5. Успех требует совпадения Order ID, intent, reference/custom/invoice ID,
   товара, количества, суммы и EUR, merchant ID, записанного при создании заказа,
   а также единственного полного Capture со статусом COMPLETED. Общий статус
   Order тоже должен быть COMPLETED. PENDING не выдаёт подарок.
6. COMPLETED и уникальное право на подарок сохраняются одной SQLite-транзакцией.
   `GET /api/orders/:id/gift` доступен только с cookie владельца оплаченного заказа.
   Только после этого frontend показывает **Celebrate Your Purchase!**.

Все `:id` в нашем API — локальные UUID, а не PayPal Order ID. Заказы других сессий
возвращают 404. POST требует точного Origin и JSON; платёжные маршруты ограничены
30 запросами в минуту на IP. CORS не включён. За будущим Nginx без отдельной настройки
trustProxy этот лимит будет общим для запросов прокси; настройка доверия — часть
будущего deployment, а не повод доверять произвольному X-Forwarded-For.

Дополнительные маршруты:

| Endpoint | Назначение |
| --- | --- |
| `GET /api/health` | HTTP 200, `{"status":"ok","service":"paypal-delight-ai"}` |
| `GET /api/orders` | Все подтверждённые покупки текущей cookie-сессии и их права/результаты, от новых к старым |
| `GET /api/orders/:id` | Сохранённое состояние заказа владельца |
| `POST /api/orders/:id/reconcile` | Прочитать состояние PayPal и подтвердить уже выполненную оплату, без нового Capture |
| `POST /api/orders/:id/cancel` | Закрыть неоплаченную попытку; при начавшемся Capture сначала сверить состояние PayPal |

## Хранение и повторы

SQLite через `better-sqlite3`: WAL, `synchronous=FULL`, foreign keys, busy timeout,
версия схемы через `PRAGMA user_version`. При первом запуске создаются `orders`
и `gift_entitlements`. Суммы хранятся целым числом центов; в PayPal передаются
десятичные строки. Сырые ответы PayPal, сведения плательщика и access tokens в БД
не сохраняются.

`orders` содержит снимок товара, сумму, EUR, статус, PayPal Order ID, merchant ID,
Capture ID (включая PENDING/DECLINED, когда ID получен), устойчивые UUID для
Create/Capture и хеш cookie владельца. Уникальные ограничения защищают Order ID,
Capture ID и `(owner_hash, client_key)`.

Повторы Create/Capture используют сохранённые `PayPal-Request-Id`. SQLite lease
на 120 секунд блокирует одновременную обработку одного заказа, в том числе двумя
процессами. После аварийного завершения процесса незавершённая операция может
оставаться занятой до истечения lease. После потерянного ответа Capture проверяется
состояние того же Order, а не создаётся новая покупка. Неопределённый Create можно
повторять в течение 5 минут; затем старый ключ не переотправляется вслепую.

Право на подарок имеет уникальный `order_id`. API показывает AVAILABLE / GENERATING /
COMPLETED; для совместимости внутри SQLite остаются AVAILABLE / RESERVED / GENERATED.
Миграция схемы v1 → v2 добавляет поля результата и lease, а также `gift_images`.
Таблица платежей и существующие права сохраняются. PNG хранится в SQLite один раз
по SHA-256, каждый подарок ссылается на него. Сохранение картинки, метаданных и
погашение права выполняются одной транзакцией. После релиза файл исходного mock
может измениться; ранее сохранённые результаты продолжают открываться из БД.
Генерация имеет timeout 60 секунд и lease 120 секунд. После падения процесса право
может оставаться GENERATING до истечения lease; следующий GET/POST безопасно вернёт
его в AVAILABLE. Токен блокировки не даёт старой операции перезаписать новый результат.
Повторное подтверждение оплаты не создаёт новое право и не сбрасывает использованное.
Этап 3C сохранял схему v2. Stage 5 выполняет добавочную миграцию v2/v3 → v4:
таблица `ai_attempts` хранит попытки подарков и резерв расхода, `ai_lab_runs` — отдельные тесты и PNG. Заказы, права
и готовые PNG не переписываются. Неопределённый AI-исход не снимает блокировку
автоматически. Инструкция проверки и ручного разрешения — в отчёте Stage 5.

После перезапуска сервера покупки сохраняются. Для повторного открытия используйте
ссылку `/?order=<локальный UUID>` **в том же браузере**. Очистка cookies, другой
профиль или истечение 30-дневной cookie лишают доступа к анонимной покупке;
аккаунты и восстановление доступа пока не реализованы. Сам UUID доступа не даёт.
В случае неизвестного результата нажмите **Check payment status** или
**Retry confirmation** для существующего заказа.

БД, WAL/SHM, `.env`, cache и приватный инфраструктурный отчёт исключены из Git.
БД нельзя включать в релизные архивы или заменять при обновлении кода. Резервное
копирование живой WAL-БД требует SQLite backup API либо остановки нового сервиса
и согласованного копирования файлов; не копируйте один `.sqlite` во время записи.

## Проверки и сборка

```powershell
npm.cmd run typecheck
npm.cmd run build
npm.cmd test
npm.cmd run test:smoke
npm.cmd run test:browser
```

- Серверные тесты: настоящий Fastify, SQLite и PayPal HTTP-клиент с подменённым
  сетевым transport. Проверяют суммы, сессии, идемпотентность, конкуренцию, restart,
  отмену, отказ, PENDING, повреждённые ответы и восстановление после сетевого сбоя.
- HTTP smoke: запускает собранный backend с отдельной временной БД, Vite dev/preview,
  проверяет health и статику. `test:smoke` требует предварительной сборки.
- Browser: `playwright-core` использует установленный Chrome/Edge/Chromium.
  При необходимости задайте `BROWSER_EXECUTABLE_PATH`. Скачивания браузера нет.
  `test:browser` требует сборки, проверяет интерфейс с симуляцией SDK v6 и PayPal API,
  но с настоящим backend и SQLite. Скриншоты сохраняются во временный каталог ОС
  и удаляются после проверки. Это не настоящая Sandbox-оплата.

Локальная проверка собранного frontend: поменяйте `APP_ORIGIN` на
`http://127.0.0.1:4173`, затем в двух терминалах запустите `npm.cmd start` и
`npm.cmd run preview`. Верните origin на 5173 для dev-режима.

## Будущее развёртывание

Сохраняется контракт `client/dist/` и `server/dist/index.js`. Для релиза нужны
корневые `package.json`/`package-lock.json`, оба workspace `package.json` и обе
директории `dist`. Запуск: `node server/dist/index.js`. Nginx должен сохранять
префикс `/api`; runtime-конфигурация может приходить через systemd EnvironmentFile.
Для загрузки фото будущий Nginx должен пропускать тело до 7 MiB (например,
`client_max_body_size 8m`); backend сохраняет собственные более строгие лимиты.
Изменения Nginx в этом этапе не выполняются.

`better-sqlite3` содержит нативный модуль: production dependencies устанавливаются
командой `npm ci --omit=dev` **на целевой Linux-системе**. Windows node_modules не
переносятся. Системный Node.js не меняется без отдельного решения. Deployment,
настройки VPS и commit/push выполняются только по отдельному разрешению.
