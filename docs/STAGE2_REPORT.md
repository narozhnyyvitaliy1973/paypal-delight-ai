# Этап 2: PayPal Sandbox Checkout

Дата приёмки: 24 октября 2026, Europe/Berlin. Локальный проект: `C:\f\proj\ha`.

Реализация и автоматические проверки завершены. Владелец выполнил настоящую
Sandbox-покупку; запись SQLite сверена с PayPal Orders API отдельным GET-запросом.
Deployment не выполнялся. Credentials, БД, диагностические материалы и
инфраструктурный handoff остаются вне репозитория.

## Подтверждённая Sandbox-покупка

- Daybreak Mug, 18.00 EUR; локальный заказ и PayPal Order имеют статус `COMPLETED`.
- В PayPal ровно один Capture со статусом `COMPLETED`, суммой 18.00 EUR и
  `final_capture=true`. Order ID и Capture ID совпадают с SQLite.
- Проверены товар, идентификаторы локального заказа и получатель платежа.
- В SQLite нет дублей PayPal Order ID / Capture ID; создано одно право на подарок
  со статусом `AVAILABLE`. `quick_check` — `ok`, нарушений внешних ключей нет.
- При сверке Capture не вызывался. Количество HTTP-попыток Capture отдельно не
  журналируется; отсутствие повторного списания подтверждено единственным Capture
  в PayPal. Повторные запросы и потеря ответа также покрыты автоматическими тестами.
- Идентификаторы конкретной транзакции переданы владельцу в локальном отчёте;
  в публичную документацию данные аккаунтов и транзакции не включаются.

## Реализовано

- Адаптивный магазин с тремя товарами: Daybreak Mug €18, Weekend Tote €24,
  Cloud Nine Headphones €79. Каталог, цены, валюта и идентификаторы — на сервере.
- PayPal JS SDK v6, EUR eligibility, официальная платёжная кнопка, обработчики
  одобрения/отмены/ошибок и восстановление redirect-сессии. SDK и API только Sandbox.
- Orders API v2 через backend: OAuth, Create, проверка Order, Capture, повторное
  чтение полного Order и проверка завершённого Capture перед выдачей подарка.
- SQLite `better-sqlite3` с WAL, FULL synchronous, транзакциями, уникальными
  идентификаторами, версией схемы и путём из окружения. Данные переживают restart.
- Идемпотентные Create/Capture и защита от одновременной обработки двумя процессами.
  Неопределённый сетевой результат восстанавливается для того же заказа.
- HttpOnly cookie покупателя, проверка Origin/JSON, строгие схемы запросов,
  ограничение частоты платёжных запросов. Секреты и сырой PayPal response не выдаются клиенту.
- Оплата и одно право на будущий AI-подарок фиксируются атомарно. Повтор не создаёт
  второе право и не сбрасывает состояние уже использованного подарка.
- Экран **Celebrate Your Purchase!** показывает подтверждённый товар, сумму и
  идентификаторы. Три режима AI пока неактивны; генерация не реализована.

## Результаты проверки

Среда: Windows, Node.js 22.15.0, npm 10.9.2, установленный Google Chrome.

| Команда | Результат |
| --- | --- |
| `npm.cmd run typecheck` | Успешно |
| `npm.cmd run build` | Успешно; `client/dist/`, `server/dist/index.js` |
| `npm.cmd test` | 38/38 серверных тестов |
| `npm.cmd run test:smoke` | 4/4 HTTP-сценария; TAP: 5/5 вместе с родительским тестом |
| `npm.cmd run test:browser` | 7/7 браузерных сценариев; TAP: 8/8 вместе с родительским тестом |

Серверные тесты проверяют реальные Fastify, SQLite и HTTP-клиент PayPal с
подменённым transport: создание, Capture, отмену, отказ, PENDING, потерю ответа,
restart, конкуренцию, транзакционный откат, подмену суммы/валюты/товара/получателя,
чужую сессию и повторную обработку. Сетевые обращения к настоящему PayPal не выполняются.

Браузерные тесты используют симуляцию SDK v6 и PayPal API с настоящим приложением:
покупка и reload, чужая сессия, отмена, declined, SDK error, redirect resume,
восстановление после потерянных Create/Capture responses. Проверены desktop и
mobile без горизонтального переполнения; необработанных ошибок страницы нет.
Дополнительно проверены переход локального Vite на `APP_ORIGIN` и создание нового
заказа после отмены. Настоящий SDK отдельно проверен в Chrome до формы входа;
саму оплату затем подтвердил владелец проекта.

Скриншоты сохраняются локально в игнорируемом `.npm-cache/`:
`store-desktop.png`, `store-mobile.png`, `purchase-success.png`.

## Границы текущего этапа

- Настоящий сценарий с Sandbox Business/Personal аккаунтами подтверждён;
  повторная проверка описана в [инструкции](SANDBOX_TESTING.md).
  При отсутствии ключей оплата отключена явно.
- Покупки анонимные и привязаны к cookie браузера. Восстановления после удаления
  cookie нет; сам URL заказа не является пропуском к покупке.
- PENDING сверяется при открытии страницы или по кнопке проверки; webhook и
  фоновый опрос не добавлялись.
- Linux-проверка нативного `better-sqlite3` отложена до разрешённого deployment.
  Тогда зависимости устанавливаются на Linux, БД размещается вне releases,
  отдельно настраиваются HTTPS/origin, Nginx и systemd.
- Для генерации подготовлено уникальное право на подарок; endpoint генерации
  и списания этого права пока отсутствует.
