# Этап 3B — Caricature Mock

Проверено локально 24 октября 2026, Europe/Berlin.

## Реализовано

- После серверного подтверждения покупки активен Caricature; Greeting Card и
  Mini Comic остаются недоступны. Существующий PayPal SDK v6 и платёжный цикл сохранены.
- Форма показывает купленный товар, необязательные пожелания (500 символов),
  необязательное фото с предпросмотром и отдельным, изначально выключенным согласием.
  Есть индикация обработки, ошибки и повторная попытка, крупный результат и Download.
- Все новые экраны доступны на DE/EN. Формы и результат прямо сообщают, что mock
  выдаёт одну подготовленную картинку, не воспроизводит внешность и не учитывает пожелания.
- Reload восстанавливает результат или ожидание. Ссылка в магазине возвращает к
  последнему подтверждённому заказу текущей вкладки. Закладка `/?order=<UUID>` работает
  при сохранении cookie владельца; одного UUID для доступа недостаточно.
- Mock использует существующий серверный PNG. Провайдер получает тип, серверный
  снимок товара, язык, пожелания и подготовленное фото. Входные фото/пожелания
  не сохраняются с результатом. OpenAI не подключён, сетевых AI-вызовов нет.

## Backend и сохранность данных

- `POST /api/orders/:id/gift` разрешён только владельцу заказа COMPLETED с правом
  на подарок. Тело: `type`, `language`, `wishes`, необязательный `photo` с base64,
  MIME и `consent`. Другие поля, цены и статусы не принимаются.
- `GET /api/orders/:id/gift` возвращает заказ и подарок. `.../gift/image` и
  `.../gift/download` проверяют владельца и завершённый результат; MIME `image/png`,
  скачивание с именем `delight-caricature-<order UUID>.png`, ответы `no-store`.
- API использует AVAILABLE → GENERATING → COMPLETED. В существующей таблице SQLite
  сохранены внутренние названия AVAILABLE / RESERVED / GENERATED, чтобы не перестраивать
  прежнюю таблицу. Ошибка возвращает право в AVAILABLE.
- Миграция `user_version` 1 → 2 добавляет поля результата/блокировки и `gift_images`.
  Схема платежей не меняется. Изображение хранится один раз по SHA-256, а подарки
  ссылаются на него. PNG остаётся доступным после restart и замены каталога релиза.
- Сохранение PNG, метаданных и погашение права — одна SQLite-транзакция. Повтор после
  успеха возвращает тот же результат; сбой записи откатывает изменения.
- Атомарный захват права работает между соединениями SQLite. Параллельный запрос
  получает HTTP 202 / GENERATING, без второго вызова провайдера. Провайдер ограничен
  timeout 60 секунд, lease действует 120 секунд. После падения процесса следующий
  GET/POST освобождает истёкший lease; ожидание может занять до двух минут.
  Токен блокировки не позволяет запоздавшей операции перезаписать новое состояние.
- Рабочая БД: `C:\f\proj\ha\data\delight.sqlite`. Проверка только на чтение при завершении разработки:
  схема v2, один COMPLETED-заказ, одно право AVAILABLE. Реальная покупка не использовалась
  разработчиком для выдачи подарка или повторного Capture. Остальные существующие заказы сохранены.
  Проверка миграции на тестовой БД сравнивает все поля платёжной записи и ID права до/после.

## Фотографии и Privacy Policy

- Проверяются отдельное согласие, 5 MiB, 16 MP, сигнатура/MIME, декодирование,
  JPEG/PNG/WebP и отсутствие анимации. Подмена MIME, SVG и повреждённые файлы отклоняются.
- Sharp учитывает ориентацию, уменьшает фото до 2048 px по стороне и пересоздаёт PNG
  без EXIF/XMP/IPTC/ICC. Теперь оригинал и очищенное фото остаются только в памяти:
  временные фотофайлы вообще не создаются, поэтому аварийный выход не оставляет их на диске.
  После вызова провайдера буферы очищаются в `finally`, в том числе при ошибке.
- Frontend отправляет фото только после Create My Gift. Отзыв согласия очищает
  выбор/предпросмотр; результат освобождает выбранный файл и пожелания в компоненте.
- Privacy Policy DE/EN обновлена под фактическую загрузку, обработку в памяти,
  сохранение результатов и возврат из sessionStorage. Данные владельца, окончательные
  сроки хранения, основания и условия будущих провайдеров остаются явными placeholders
  для заполнения и проверки перед публичным размещением.

## Ручная проверка

1. В корневом `.env` используйте `AI_PROVIDER=mock` (это также значение по умолчанию).
   Не добавляйте OpenAI-ключ. Существующие Sandbox-настройки оставьте прежними.
2. Из корня проекта запустите в двух терминалах:
   `npm.cmd run dev:server` и `npm.cmd run dev:client`.
3. Откройте адрес из `APP_ORIGIN` — в текущей настройке проекта `http://localhost:5173`.
   Используйте тот же профиль браузера и cookie, что при успешной покупке.
4. Вернитесь к оплаченной покупке по сохранённому `/?order=<UUID>` или через
   восстановленную вкладку. Для нового тестового заказа оплатите Sandbox Personal
   account, отличным от продавца; это ручное действие владельца проекта.
5. На Celebrate нажмите Caricature. Оставьте форму без фото или включите отдельное
   согласие и выберите JPEG/PNG/WebP. При желании заполните пожелания.
6. Нажмите Create My Gift → дождитесь результата → Download PNG.
7. Обновите страницу, вернитесь в магазин и нажмите ссылку возврата к последнему
   подарку. Должен открыться тот же результат без новой генерации и оплаты.
